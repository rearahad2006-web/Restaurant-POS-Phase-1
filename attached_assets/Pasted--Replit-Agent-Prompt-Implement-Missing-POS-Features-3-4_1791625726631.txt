## FEATURE 1 — DEALS / COMBO OFFERS

### A. Manager Deals page

Add a **Deals** page to the existing Manager Panel.

Managers must be able to:

- View existing deals.
- Create a deal.
- Edit a deal.
- Activate or deactivate a deal.
- Delete a deal, with sensible confirmation if needed.

Each deal must support:

- Unique ID
- Deal name
- Optional description
- One or more existing menu items
- Quantity required for each included item
- Fixed deal price in PKR
- Active/inactive status

Example:

**Rice & Drink Combo**
- Chicken rice × 1
- Cold drink × 1
- Deal price: PKR 500

Use the existing menu items and their IDs. Do not create duplicate menu products.

Persist deals through the project's existing storage/repository approach so they remain available after refreshing the page.

### B. POS integration

Add a clear **Deals / Combos** section to the existing POS.

- Show only active deals to cashiers.
- Display the deal name, included items, quantities, and fixed price.
- Allow the cashier to add a deal to the current cart.
- Allow increasing, decreasing, manually editing, and removing a deal's quantity.
- Recalculate the cart totals correctly.
- Keep ordinary menu items and deal entries separate in the cart.

**Pricing must be correct:**

- A combo is charged at its fixed deal price.
- Do not additionally charge the individual menu prices for the components included in that combo.
- If a customer orders an included item separately, charge that separate item normally.
- Changing the quantity of a deal must update its total correctly.
- Preserve existing discounts, delivery charges, and order-type behavior.

### C. Save deal snapshots in completed orders

When an order is completed, save the information needed to reproduce the original deal on historical orders and receipts:

- Deal name
- Included item names
- Included item quantities
- Quantity of deals purchased
- Fixed deal price per deal
- Total deal price

Editing or deleting a deal later must not change completed orders, old receipts, or historical sales.

Keep older orders compatible if they do not contain deal information. Do not erase or reset existing saved orders.

### D. Permissions

- Managers can create, edit, activate/deactivate, and delete deals.
- Cashiers can view and select active deals in the POS.
- Cashiers cannot access deal-management pages or actions.
- Use the existing role checks and protected-route approach.
- Do not rely on hiding a navigation link alone; protect the actual management route/actions too.

## FEATURE 3 — MANUAL QUANTITY ENTRY

Improve the existing POS cart quantity controls.

Keep the existing plus (+), minus (−), and remove-item buttons.

### Required behavior

The cashier must be able to click the quantity number, type a new quantity, and press Enter or move focus away to apply it.

Example:

- Current quantity: 2
- Cashier types 15
- Presses Enter
- Quantity becomes 15
- Line total and order totals update immediately

Requirements:

- Accept positive whole-number quantities only.
- Support normal menu items and deals.
- Support Dine-in, Takeaway, and Delivery.
- Recalculate line totals, subtotal, discounts, delivery charges where applicable, and grand total.
- Keep remove-item functionality working.
- Do not submit or complete the order accidentally when Enter is pressed in the quantity field.

### Validation

- Reject zero, negative numbers, decimals, and non-numeric entries.
- Allow the field to be temporarily empty while the cashier is editing it.
- Do not remove an item merely because the field is temporarily empty.
- When invalid input is committed, restore the previous valid quantity and show a small, clear validation message if appropriate.
- Prevent invalid quantities from entering the saved order.
- Never modify completed orders when the cashier edits the current cart.
